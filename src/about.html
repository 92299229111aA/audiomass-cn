介绍 AudioMass（https://audiomass.co），一款开源的网页音频与波形编辑工具。

AudioMass 可以录音，也可以编辑已有音轨。你可以裁剪、剪切、粘贴，以及应用压缩、参数均衡、混响、延迟、音频修复和音高／速度曲线等效果，还能进行多轨混音导出。它支持快捷键、离线使用和自适应界面，让快速编辑保持高效。 它完全使用传统的原生 JavaScript 编写，压缩后不足 100 KB，不依赖后端或前端框架。

它也兼容多种浏览器和设备。

开始使用

首先拖放一个音频文件，或试用内置示例。
文件加载并显示波形后，可以缩放、平移或选择一个区域。

波形工具

主编辑器围绕快速区域编辑设计。选中一段波形后，可剪切、复制、粘贴、裁剪、静音、反转、反相，或仅处理该区域。界面还提供频率可视化、峰值和失真提示以及过零点选择，帮助你发现明显问题并避开生硬的剪辑点。

标记与定位点

标记是可以放在波形重要位置的小型命名定位点。按 [M]，双击顶部标尺，或右键选择 在此处添加标记。你可以拖动、重命名或删除标记，也可以用 [ 和 ] 跳转；跳转时按住 [Shift]，还可快速将标记之间的内容设为选区。这个小工具在编辑较长音频时很有用。

节拍工具

AudioMass 可以粗略检测节奏、绘制节拍器节拍线，并让编辑位置吸附到节拍。它有助于制作循环、重复段落和修正时序，同时保持编辑器简洁。

效果与处理

AudioMass 提供增益、淡入淡出、压缩、标准化、混响、延迟、失真和音高变换等常用处理工具。图形化音高／速度曲线可制作渐变和多普勒效果；修复工具可处理点击声、嗡声与生硬的剪辑点。应用前可以预览，大多数效果既可作用于当前选区，也可作用于整个文件。

制作无缝循环

选中一个区域后，使用 编辑 > 无缝循环，或右键点击波形并选择 无缝循环。AudioMass 会打开循环预览，你可以调整交叉淡化、裁除边缘静音、吸附到更平滑的过零点，点击预览位置试听、重复播放，然后将结果应用到文件或在新编辑器标签中打开。

撤销与离线使用

AudioMass 会保存编辑操作的撤销历史，方便你尝试不同处理。它在浏览器本地运行，不需要后端；加载完成后还可离线继续使用。

录制音频

要录制音频，点击录音按钮或按 [R] 键。

导出为 MP3

要导出 MP3，请点击“文件”→“导出 / 下载”，然后按照弹窗中的说明操作。

AudioMass 的故事，以及我对网页界面的一点感想

我在 2018 年 6 月写下 AudioMass。它一直躺在硬盘里，直到 2019 年 7 月 13 日我决定把它分享出来（你看到它时可能已经是 2020 年了，你好！）。 起初它只是供我快速查看波形的小工具，后来加入剪切、复制、粘贴和淡入淡出。随着功能不断增加和对细节的追求，我开始尝试：在保持可接受的性能与较小体积的同时，它能有多接近功能完整的波形编辑器？

总的来说，我很喜欢数字音频工作站（DAW）的界面：它们复杂、精细且功能多样，却能在无数选项和旋钮之间保持良好的视觉体验。我常觉得网页界面的发展走了弯路，看看这些出色的界面……

构建界面

假设我们有一个 "PLAY" 按钮，点击后音轨开始播放。我们希望按钮的颜色和状态能反映播放状态。最直接的写法可能是：

btn.onclick = function () {
	this.classList.add ('active');
};

如果还有触发同一操作的快捷键呢？假设按下 [SPACEBAR] 后音轨开始播放，是否还要在空格键的处理函数中修改按钮的样式？

document.onkeypress = function ( e ) { 
  if ( e.keyCode === 32) {
       e.preventDefault ();

       document.querySelector ('.playbtn').classList.add ('active');
  }
};

如果有两个按钮，或者其中一个被动态移除，又该怎么办？要遍历所有按钮吗？
如果音轨正在播放，这时再次按 [SPACEBAR] 或点击播放按钮，就需要停止播放。此时又该如何处理？可以看出，界面很快就会变得混乱，各部分紧密耦合。

引入观察者模式后，操作由事件表示。上面的逻辑可以写成：

btn.onclick = function () {
	FireEvent ('RequestTogglePlay');
};

On ('WillPlay', function () {
	btn.classList.add ('active');
});

On ('WillStop', function () {
	btn.classList.remove ('active');
});



document.onkeypress = function ( e ) {
  if ( e.keyCode === 32) {
       e.preventDefault ();

       FireEvent ('RequestTogglePlay');
  }
};



On ('RequestTogglePlay', function () {
	if (track.is_playing) {
		FireEvent ('WillStop');
		track.stop ();
	}
	else {
		FireEvent ('WillPlay');
		track.play ();
	}
});

track.onPlayStart = function () {
	FireEvent ('DidPlay');
};
track.onPlayStop = function () {
	FireEvent ('DidStop');
};

这样各部分就解耦了。按钮根据收到的事件更新状态，而按钮和空格键使用同一套机制。你可能注意到了这里使用的术语："Request"、"Will" 和 "Did"。这些名称是为了让结构更清晰而选定的。
"Request" 表示执行操作的意图，但操作未必能执行，例如对象尚未初始化或仍在加载。 "Will" 表示条件已满足，正准备执行操作；而 "Did" 表示操作刚刚完成。
这种方式可能略显繁琐，却很好地组织了 AudioMass 的界面。

可停靠界面

我喜欢数字音频工作站的一点是：每个窗口都可以从主界面分离。我还记得曾让 VST 插件铺满三块屏幕。那么浏览器中能否做到这一点？

可以，而且用的是很传统的方法：通过 window.open 创建弹出窗口，再向它的 documentWindow 对象传入缓冲区。除了旧版 IE Edge，性能出乎意料地好；我猜它会将每个数据包序列化为 ASCII 或 Base64。Chrome 也有个有趣的问题：无法传入超过 512 字节的缓冲区。

分离窗口使用 window.open。停靠时又该如何实现？如果为独立页面和页内脚本各写一套相同功能会很繁琐。使用 iframe 就能复用同一个页面。

两者的唯一区别是：分离窗口通过 window.opener 引用父窗口，而 iframe 使用 window.parent。

多轨 （2026 年回归！）

还记得我说过下一个重要功能会是多轨支持吗？它终于来了。AudioMass 现在有了真正的多轨模式：叠放多条音轨、混合它们，再将结果导出为单个文件。它就像在常规波形编辑器上加了一套小型数字音频工作站，共用引擎、快捷键和效果。

点击顶部的 多轨 按钮，就会开启带有几个空声道的新会话。将音频文件拖到音轨或画布上的任意位置，文件便会落在该处。每个文件会成为一个片段，可以在所属轨道上自由拖动。

拖动片段边缘可裁剪，拖动角落的小手柄可设置淡入或淡出；使用 [Ctrl/Cmd + X] 可在播放头处分割。片段也可复制、建立副本、重命名或删除。同一音轨上的两个片段重叠时，AudioMass 会自动在重叠处绘制交叉淡化，使衔接平滑。片段移动时，交叉淡化会随之调整。

每条音轨的标题栏都有音量、声像、静音、独奏和预备录音控制。小圆形旋钮可上下拖动连续调节，双击可重置。另有独立的混音器视图，适合偏好竖向通道条和大电平表的混音操作。

录音方式与单轨编辑器相似，但会录到已设为预备录音的音轨。你可以从指定位置录入并通过电平表监听；停止后，录音立即成为可移动、可编辑的普通片段。同一音轨可以叠放多次录制的内容，不会丢失先前的片段。

效果可应用于整个片段，也可只应用于其中一个区域。处理通过 OfflineAudioContext 完成，因此在确认应用前不会破坏原音频，并且可以实时预览。撤销历史也涵盖每一次片段编辑，方便自由尝试。

整个会话，包括音轨、片段、淡化和旋钮数值，都可以保存为 .amss 文件。它封装原始音频和描述布局的 JSON，并使用 LZMA 压缩。以后重新载入即可接着编辑。导出最终混音时使用混音导出，所有内容经离线渲染合成为单个 WAV 或 MP3 文件。

拖动时可以吸附到片段边缘、播放头和选区。移动端也支持触摸手势、在时间轴上双指缩放以及长按打开菜单。它并非 Pro Tools，但足以在浏览器标签页中快速编排录音、制作播客或拼接灵感。:)

许可证

AudioMass 本身采用 MIT 许可证。我希望它始终免费且实用：你可以使用、修改、学习或发布它。部分随附库采用各自的许可证，多数为 BSD 类许可证；MP3 编码器采用 LGPL。仓库中的第三方声明文件列出了完整清单。许可证的法律效力以原始英文文件为准。

后续工作与性能考量

几乎每个方面都还有很大的改进空间。

首先，可以移除当前用于渲染波形的库，将文件大小再减少约 20 KB。我们只使用了这个库的一小部分功能，无需完整引入。

波形渲染也有很大优化空间。我已经大幅修改该库，使其只计算并绘制可见区域；但每一帧仍会清空并重绘整个画布。可以利用 2D Context 的 translate 方法移动画布，减少像素重绘。

还可以将滤波器处理等操作移到后台线程，避免应用较长效果链时界面卡顿。


不过，遇到的最大问题来自 Web Audio API。每次操作都需要在每一帧遍历多个长数组，最终触发垃圾回收，造成爆音。使用较小的 fftSize 可以缓解，却会限制可处理的频率范围。纯 WASM 实现或许比使用 JavaScript 修改音频信号性能更好，只有试过才知道。:)

此外，decodeAudioData 不提供进度回调，也无法取消。因此加载很大的音频文件时，在处理完成前会持续占用资源；如果误选了大文件，这一点尤其烦人。目前还没有绕过这个限制的方法。
